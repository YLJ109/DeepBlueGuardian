# 深蓝智护 · 国赛一等奖冲刺方案（移动端 + 功能增强 + 演示视频）

> 版本：v1.0　日期：2026-10-06
> 适用范围：中国大学生计算机设计大赛 · 赛道 B（应用赛道）· 国赛
> 本文档为「先方案、后实现」的规格书；实现完成后回填验收结论。

## 一、能冲国一吗：现状体检

按国赛评审的五个维度自评（评委视角，不自我美化）：

| 维度 | 当前水平 | 国一水位 | 差距判断 |
| --- | --- | --- | --- |
| 选题价值与场景真实性 | 9 / 10 | 8.5 | **达标**。连江海洋牧场 + 红树林 + 海漂垃圾，场景具体、痛点真实、非"PPT 项目" |
| 技术含量与创新性 | 7 / 10 | 8.5 | **偏弱**。赤潮模型训练集为物理机理仿真、硬件为仿真上报，AI 部分只有"模型跑通"，缺自有数据闭环 |
| 完成度与工程质量 | 8.5 / 10 | 8 | **达标偏好**。大屏 / 后台 / 11 个后端模块 / 自动化校验齐全，可现场演示 |
| 实用价值与可推广性 | 6.5 / 10 | 8 | **主要短板**。只有桌面端，缺"现场侧"闭环；无落地量级、低成本复制、可推广证据 |
| 演示与答辩表达 | 7 / 10 | 8.5 | **待提升**。视频未覆盖图像识别与移动端，故事线还是"功能罗列"而非"业务闭环" |

**结论：目前是「稳国二、冲国一」的水平。** 差距集中在四件事：

1. **只有桌面端**。真实海洋巡护一定发生在岸边、船上、手机里，评委看不到"现场侧"。
2. **业务纵深不够**。平台停在"看数据 + 预警"，缺「派任务 → 现场核查 → 上报证据 → 复盘归档」的闭环。
3. **可推广性没有证据**。没有"一个县做成、N 个县能用"的表述与配置化能力展示。
4. **演示视频还是功能罗列**。没有把「识别到垃圾 → 派单 → 手机到场 → 拍照复核 → 生成报告」串成一个故事。

**冲刺目标（三句话）**：把平台从"桌面端监测系统"升级为**「桌面端决策 + 移动端执行」的双端闭环**；把 AI 从"跑通模型"升级为**"自有数据可采集、可回流、可再训练"**；把演示从"讲功能"升级为**"讲一次真实的处置全过程"**。

## 二、功能增补清单（本次实现 4 项）

| 编号 | 功能 | 为什么国一必须有 | 优先级 |
| --- | --- | --- | --- |
| F1 | **巡护任务派发与闭环** | 补齐"监测→处置"业务纵深，桌面派单、移动执行，是整条故事线的主干 | P0 |
| F2 | **移动端拍照即识别** | 把自训练海漂垃圾模型搬到现场：手机拍照 → 真实推理 → 一键转告警 | P0 |
| F3 | **移动端语音问数** | 展示大模型 + 智能体的多模态入口，船上/岸边不方便打字 | P1 |
| F4 | **巡检报告一键生成** | 把一次巡护的水质、告警、识别结果、处置记录汇成可打印报告，答辩可现场出具 | P1 |

### 为什么不做这几件事

- 不引入新的重型模型（U-Net / 时序 Transformer）：无自有标注数据，硬上只会变成"跑得动但说不清"的负分项。
- 不做真实硬件通信：无实物浮标，保持 `source` 标注的仿真口径，不冒充实测。
- 不做 App 打包（Android/iOS）：H5 + 响应式已足以演示且零安装成本，符合"县域低成本复制"叙事。

## 三、移动端方案（与桌面端功能分工）

**设计原则：移动端不是桌面端的缩小版。** 桌面端负责"看全局、做决策、管配置"；移动端负责"在现场、出任务、留证据"。

| 能力 | 桌面端（大屏 / 后台） | 移动端（H5） |
| --- | --- | --- |
| 三维孪生沙盘 | ✅ 主场景 | ✖ 不做（手机性能与信息密度都不合适） |
| 全域态势 / 多区域对比 | ✅ | 只给"我负责的片区" |
| 设备台账增删改、阈值配置 | ✅ | ✖（只读扫码查设备） |
| 巡护任务派发与调度 | ✅ | ✅ 领取 / 到场 / 拍照 / 提交 |
| 海漂垃圾识别 | ✅ 桌面样本与录像巡视 | ✅ **手机相机直拍直传** |
| 智能体问答 | ✅ 文字 + 流式 | ✅ **语音提问 + 语音播报** |
| 告警处理 | ✅ 批量筛选与处置 | ✅ 一键处置 + 到场导航 |
| 巡检报告 | ✅ 生成与导出 | ✅ 查看与分享 |

### 移动端信息架构（底部 5 个 Tab）

1. **首页 · 我负责的海**
   我负责片区的实时水质卡（水温 / 溶解氧 / pH / 叶绿素a）+ 赤潮风险等级 + 待办任务数 + 最近一条告警；下拉刷新。
2. **巡护 · 任务**
   任务列表（待领取 / 进行中 / 已完成），点开看详情与要求；**领取 → 到场打卡（浏览器定位）→ 拍照识别 → 填写情况 → 提交**；提交时把图片 SHA-256、识别结果、经纬度、时间一并存证。
3. **识别 · 拍照即测**
   调起手机相机拍照或从相册选图 → 调用海漂垃圾检测模型 → 显示带框结果、类别、置信度 → **一键转告警**或**提交到当前任务**。
4. **告警 · 处置**
   待处置 / 已处置两段；每条给等级、位置、时间、建议；点"去处置"弹出处置意见（可语音输入），提交后状态变更并写入审计。
5. **我的 · 助手与设置**
   当前账号与角色、负责区域；语音问数入口（长按说话）＋ 最近问答；退出登录。

### 移动端专属交互（桌面端没有）

- **相机直连识别**：`<input type="file" accept="image/*" capture="environment">`，拍照后前端压缩 → base64 → 后端识别节点。
- **语音提问 + 语音播报**：浏览器语音识别转文字 → 复用智能体接口 → 播报回答（无语音识别能力时自动降级为文字输入，不假装支持）。
- **到场定位**：`navigator.geolocation`，拒绝授权时如实提示"未获取定位"，不编经纬度。
- **任务打卡存证**：提交内容计算 SHA-256，写入任务证据链与审计日志，展示存证指纹。

## 四、技术实现要点

### 4.1 后端新增：巡护任务模块 `/api/v1/patrol`

数据表 `patrol_task`：

| 字段 | 说明 |
| --- | --- |
| `task_code` | 任务编号 PT + 日期 + 序号 |
| `title` / `detail` | 任务标题与要求 |
| `region_code` / `device_code` | 关联区域与设备 |
| `priority` | normal / high / urgent |
| `status` | pending 待领取 / working 进行中 / done 已完成 |
| `assignee` / `created_by` | 执行人与派发人 |
| `due_at` | 截止时间 |
| `lat` / `lon` / `location_note` | 到场位置 |
| `evidence` | JSON：图片哈希、识别结果、置信度、类别 |
| `result_note` | 现场情况与处置说明 |
| `digest` | 提交内容的 SHA-256 存证指纹 |
| `created_at` / `started_at` / `finished_at` | 时间轴 |

接口：

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/patrol/tasks` | 登录 | 任务列表（按状态/区域/执行人筛选） |
| POST | `/patrol/tasks` | 技术员及以上 | 派发任务 |
| GET | `/patrol/tasks/{code}` | 登录 | 任务详情与证据 |
| POST | `/patrol/tasks/{code}/claim` | 登录 | 领取任务 |
| POST | `/patrol/tasks/{code}/submit` | 登录 | 提交现场记录（含存证） |
| GET | `/patrol/summary` | 登录 | 任务统计（待领取/进行中/完成率/平均时长） |
| GET | `/patrol/report` | 登录 | 巡检报告数据（按时间窗聚合水质、告警、识别与任务） |

### 4.2 前端新增

- `frontend/mobile.html` + `frontend/assets/mobile.js`：移动端 H5（Vue 3 全局构建，复用 `theme.css` 令牌与组件类）。
- `frontend/console.html`：新增「巡护任务」页（派发、看板、生成报告），与移动端同源同接口。
- 路由：`/m` 指向移动端（由 FastAPI 静态托管，与 `/console` 一致）。

### 4.3 数据真实性纪律（沿用现有口径，不放松）

- 识别结果 100% 来自模型对上传画面的真实前向推理，识别不到就显示"未识别到关注目标"。
- 演示样本来源逐张标注，移动端同样显示来源说明。
- 仿真水质数据保持 `source=sim` 标注，页面口径与桌面端一致。
- 定位、语音、拍照任一能力不可用时如实降级提示，不做假可用。

## 五、演示视频方案（4–5 分钟，本轮不动剪辑）

总时长目标 **4 分 30 秒**，结构：**开场海报 → 目录 → 项目背景 → 数字孪生大屏 → 巡护任务闭环（跨桌面与手机）→ 图像识别 → 赤潮预警 → 红树林 → 生态智能体 → 账户与审计 → 应用价值 → 结束海报**。

| 段落 | 时长 | 画面 | 旁白要点 | 海报 / 转场 |
| --- | --- | --- | --- | --- |
| 开场 | 8 s | 品牌主视觉 | 深蓝智护，连江海洋生态智能监测平台 | 开场海报 + 渐显 |
| 目录 | 8 s | 五大板块 | 本次演示分为五个部分 | 目录海报 + 滑动切场 |
| 项目背景 | 14 s | 连江海域与痛点 | 22 台设备、7 个区域，人工巡检成本高 | 背景海报 + 数据翻页 |
| 数字孪生大屏 | 35 s | 三维沙盘全域 | 一屏统管、实时水质、风险分布 | 大屏海报 + 推镜 |
| **巡护闭环** | **45 s** | **桌面派单 → 手机领取 → 到场拍照 → 识别 → 提交 → 桌面看板** | 从发现到处置形成闭环 | 双端同框转场 |
| **图像识别** | **30 s** | 视频 AI 识别页 + 手机拍照识别 | 自训练模型识别塑料、泡沫、废弃渔具 | 识别海报 + 框选动效 |
| 赤潮预警 | 30 s | 模型指标 + 预警触发 | 四级风险、48 小时窗口、贡献因子 | 模型海报 |
| 红树林 | 25 s | 遥感分割与变化检测 | 面积变化与健康度 | 遥感海报 |
| 生态智能体 | 35 s | 对话 + 工具调用 | 自然语言问数，取真实数据 | 智能体海报 |
| 账户与审计 | 20 s | 权限与留痕 | 角色隔离、写操作全留痕 | 审计海报 |
| 应用价值 | 20 s | 价值提炼 | 低成本可复制、可推广到其他县域 | 价值海报 |
| 结束 | 10 s | 品牌落版 | 感谢聆听 | 结束海报 + 淡出 |

技术手段（后续实施）：Remotion / HyperFrames 做海报与转场动效，FFmpeg 合成，画面切换配转场音效，BGM 与旁白做侧链闪避（沿用现有 `build_final.py` 的混音链），旁白用统一音色，字幕时间轴全部取整秒。

## 七、风险与边界

| 风险 | 应对 |
| --- | --- |
| 手机端相机在桌面浏览器无法真机验证 | 用 Playwright 模拟文件上传路径；真机演示时用 Chrome 摄像头权限，演示前预演一次 |
| 语音识别依赖浏览器能力 | 不支持时自动切换文字输入并提示，不假装支持 |
| 定位在无 GPS 的电脑上取不到 | 允许手填位置说明，未获取时如实标注"未定位" |
| 新增页面拉长演示路径 | 移动端每步操作控制在 2 次点击内，演示主线只走一条最短路径 |
